# Проверка функций BilBook

Локально пройдены 28 тестов Vitest: SQL-миграция выполняется в PGlite с моделированием auth/storage, отдельно проверяются HTTP-защита и частичные ошибки очистки. Это не заменяет проверку на подключённом Supabase.

| Сценарий из задания | Реализация | Что ещё проверить после подключения |
|---|---|---|
| Приглашения, email, вход и восстановление | Auth API, формы, триггер приглашения, callback | Доставка SMTP, переходы по письмам, реальные сессии |
| Профиль и роли | Профиль, назначения администратором, RLS | Создание первого администратора по bootstrap.sql |
| Истории | Фото, предпросмотр, сжатие, просмотр, удаление, жалобы, лимит 5/24ч | Загрузка в настоящий Storage с телефона |
| Истечение и очистка | RLS по expires_at, ограниченные ссылки, очередь повторных удалений | Подписанные URL Storage и cron на хостинге |
| Новости | Четыре категории, назначенные редакторы, фото, лайки, пагинация | Сквозной сценарий нескольких реальных аккаунтов |
| Публичные обращения | Проверка модератором, поддержка, статусы, ответы, история | Приём и обработка обращения в подключённой школе |
| Конфиденциальные обращения | Автор и назначенные взрослые, защита текста/фото/автора | Проверка ролей на настоящих Supabase JWT |
| Управление | Приглашения, пользователи, блокировка, жалобы, публикации, журнал | Назначить сотрудников школы |
| Удаление аккаунта | Повторная проверка пароля, очередь фото, защита последнего админа | Реальный Auth delete + Storage |
| PWA | Manifest, иконки, инструкция установки, отсутствие приватного офлайн-кэша | Установка на Android/iPhone после HTTPS-деплоя |

Интерфейс, TypeScript и production-сборка проверены локально. GitHub, Supabase и Vercel не подключены и не опубликованы. Поэтому нельзя считать письма, облачное хранение и плановую задачу проверенными в рабочей среде. Инструкции подключения находятся в README и docs/VERIFICATION.md.
