# Вход, профили и друзья

Подготовлено 22 октября 2026. Этот выпуск требует SQL-миграции до публикации приложения.

## Включение

1. В Supabase → SQL Editor выполните целиком `supabase/migrations/202610220001_profiles_friends.sql` после исходной миграции. Скрипт выполняется одной транзакцией, повторный запуск после успеха не требуется.
2. Для Google: в Google Auth Platform создайте OAuth Web client. Origin: `https://bil-book.vercel.app`; redirect URI — callback URL из Supabase Authentication → Sign In / Providers → Google (`https://<project-ref>.supabase.co/auth/v1/callback`). Внесите Client ID и Client Secret в Google provider Supabase. Секрет не нужно отправлять в чат или GitHub. Разрешения — openid, email, profile.
3. В Supabase URL Configuration оставьте Site URL `https://bil-book.vercel.app` и Redirect URL `https://bil-book.vercel.app/auth/callback` (а также существующий callback восстановления).
4. После подтверждения миграции публикуйте код. До настройки провайдера кнопка Google объясняет недоступность; email/password остаётся рабочим способом входа.

Официальная инструкция: https://supabase.com/docs/guides/auth/social-login/auth-google

## Поведение

До входа показывается самостоятельная страница регистрации/возвращения. После Google новая учётная запись не имеет школы и доступа к материалам. Завершение регистрации требует имени, фамилии, типа участника, класса для ученика и действительного приглашения. Пока в интерфейсе одна школа: ШЫМКЕНТ БИЛ #1 для юношей. Реальная школа определяется проверенным приглашением, не клиентским полем.

Ученик выбирает 7–11 и A/B/C. Учитель может выбрать классное руководство или оставить без класса. Выбор учителя — заявка, не выдача роли: администратор подтверждает её через управление участниками. Доступ к конфиденциальным обращениям отдельно назначается взрослому сотруднику.

Описание профиля — до 300 символов. Раздел «Люди» ищет имя/фамилию внутри школы, фильтрует по классу, учителям, друзьям и входящим/исходящим заявкам. Принять заявку может только получатель. Можно отменить, отклонить заявку или удалить дружбу. На пару людей существует одна запись.

## Проверенные границы безопасности

- Приглашение проверяется и расходуется транзакционно. Google provider проверяется по серверным app metadata, не по произвольным user metadata.
- Новая Google-учётная запись без вступления не читает школьные данные. Авторизация и подтверждение email обязательны для вступления и социальных операций.
- Нельзя самому выдать роль учителя/администратора или доступ к личным обращениям.
- Поиск не выдаёт email и не включает чужие школы, заблокированные и неподтверждённые аккаунты.
- Прямые записи в friendship-таблицу запрещены; RPC проверяет школу, стороны, операции и лимиты. До 20 новых заявок в сутки, до 50 незавершённых, 30 операций в минуту.
- Реестр дружбы виден только сторонам. Сторонний участник не видит, кто с кем дружит.
- Описание выводится как текст React, без HTML; длины и классы проверяются сервером и SQL.
- Сохранены Origin-защита, HttpOnly cookies, RLS, приватное Storage, короткие подписанные ссылки и no-store для приватных ответов.

## Проверки и ограничения

TypeScript и production-сборка прошли. Проверки на настоящей PostgreSQL-совместимой PGlite базе выполняют обе миграции, старые сценарии доступа и новые сценарии регистрации/дружбы. Runtime npm audit: 0 известных уязвимостей на момент проверки.

22 октября 2026 миграция проверена на облачном проекте: поля профиля, таблица friendships и RPC enroll/people/command доступны. Google OAuth настроен для проекта BilBook, режим Google Auth Platform — In production. Разрешения: openid, userinfo.email, userinfo.profile. Client Secret хранится в настройках Google provider Supabase и не включён в репозиторий. Site URL и callback указывают на https://bil-book.vercel.app.

Проверен полный вход на рабочем сайте: кнопка Google → выбор существующего аккаунта → consent → callback → профиль текущей школы. Существующая подтверждённая учётная запись сохранила профиль. Раздел «Люди», фильтр класса и форма профиля загружаются; полный обмен заявками между двумя реальными аккаунтами в production не выполнялся. Сценарии дружбы проверены тестами базы данных.

Публичные страницы /privacy и /terms опубликованы и связаны с формой входа и экраном согласия Google. Для аккаунта только с Google, у которого ещё нет пароля, удаление запрашивается через контакт администратора; текущее самостоятельное удаление требует пароль. Бренд Google не отправлялся на проверку: экран Google может показывать домен проекта Supabase вместо названия BilBook.

Это не обещание отсутствия всех рисков. Для массового набора школе также нужны собственный SMTP и контроль выдачи приглашений.
